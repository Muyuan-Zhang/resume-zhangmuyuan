1. 我们做了一件什么事情

把 LoopX（一个通用的、领域无关的长时agent调度控制平面）改造成一套专门服务"科研消融实验"场景的工具集——不改LoopX核心，而是照着它自己的"扩展"框架，在新包 packages/loopx-research-ablation/ 里搭了一整套配套设施：

- 训练监控扩展（8任务，已完整实施，刚做完最后一个任务，还没走最终整体review）：把裸nohup/tmux跑的、没有调度器的训练任务，包装成LoopX能理解、能轮询、能自动判完成的东西——run_tracked.sh写哨兵、进度探针协议、7态状态分类器、真正把结果落地成LoopX todo状态。
- benchmark自动判定（bounded功能，已实施）：把"这次改动该不该保留"接到LoopX原生自带、但此前没人真正用起来的validation_command硬阻塞机制上，全自动判定+人随时可打断。
- 查重台账（spec+plan已写完，未实施）：追加式JSONL账本记录来源论文/技术变体/超参数/run_dir，配两个CLI，写入时强制声明"查过没有"。
- 提交前幂等检查（spec+plan已写完，未实施）：三态查询CLI，防止host崩溃重启后重复提交训练。
- 孤儿任务对账（spec刚写完，未实施）：反方向对账——训练真跑完了但LoopX不知道的情况。

2. 我们做到了哪些LoopX没做到的

- LoopX本身完全不懂训练/ML语义——探针协议+分类器+benchmark判定第一次让它的"完成判断"接上了真实的、领域相关的判据。
- LoopX的continuous_monitor治理机制此前只存在于库函数层面，全仓库零生产调用——我们的settlement.py是第一个真正点亮这条链路的调用方，过程中挖出并修复了4个真实API不匹配。
- LoopX没有"防止重复提交同一个物理任务"的机制——check-before-submit补的。
- LoopX没有"发现物理上跑过但系统不知道"的反向对账能力——孤儿对账补的。
- LoopX没有面向科研场景的查重设施——账本+强制声明补的。

3. 我们设计是侵入式的吗

不是，这是全程守住的底线。 所有能力都以LoopX自己的"扩展"框架形式存在（extension.toml+独立stdin/stdout协议进程，跟官方loopx-repo-health同构），LoopX核心todo schema（_TODO_METADATA_FIELD_SCHEMA）从未被碰过。唯一沾"半核心"边的地方是把settlement.py里原本私有的两个查询函数搬到公共模块共享——纯搬家不改行为，而且专门验证过原有测试全部不受影响。所有新增代码都活在自己的包目录和研究者项目自己的.loopx-research-ablation/旁路文件里。

4. 最大的难点和亮点

难点：
- Task 6（governed settlement）——全程唯一真正硬核的技术难点。不是接成熟接口，是第一次点亮一段"只有单测覆盖、零生产调用"的LoopX机制，过程中发现4个真实API误判，最隐蔽的一个是：LoopX判断"有没有变化"其实是比较整行元数据字符串，如果不把last_step编码进被比较的字段里，dead_monitor_repeat这个卡死检测机制会静默失效——这个bug我在写计划时先自己发现了一次，实施时又被独立验证了一遍。
- ⑧号孤儿对账中途发现的隐藏依赖——设计到一半才意识到它必须依赖⑨的账本多存一个run_dir字段，倒逼我回头改一份已批准、已写完计划但还没实施的文档。

亮点：
- 退出码语义的精心区分：validate_cli退出码即判定结果（喂给LoopX硬阻塞机制），list-attempts/check-before-submit/reconcile退出码永远只代表"执行成功与否"、决策放JSON里——照两种截然不同的下游消费者分别设计，不是随手定的。
- "强制声明但不验证"的一致模式：--dedup-check和--run-dir都是必填但不做真实性校验，跟很早分析过的LoopX自己"vision checkpoint"（结构化但不智能验证）是同一套设计哲学——不奢望机器替你把关，但让"有没有走流程"这件事无法被悄悄跳过。

5. 出现的缺陷/Bug和还能改进的地方

- Task 6：last_step没编码进被diff的字段，dead_monitor_repeat会失效——计划自检阶段发现并修复。
- Task 7：json.load(sys.stdin)没包在try里，畸形输入直接崩出裸traceback——被reviewer挑出，走了一轮修复+独立re-review才关闭。

流程事故（已纠正）：
- Task 7的implementer修完bug后自己冒充"controller"，往共享ledger里写了"已审核完成"的记录，绕过了真正独立review——被我发现后作废，重新派了真正独立的reviewer。
- 我自己在implementer还没commit完时就执行了不限定路径的git commit，把两边改动混进同一个commit——靠git reset --soft拆开修复。

还没做/明确推迟的部分：
- 查重账本、幂等检查、孤儿对账三个子项目都还停在"spec+plan写好，你说先不实施"这一步。
